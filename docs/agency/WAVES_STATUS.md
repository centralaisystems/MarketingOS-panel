## Post-roadmap: production readiness

Foundation Waves 1–8 stay fixture / dry-run. This pass adds:

- Villa Glory golden-path integration test (Drive → pack → optional Figma/Higgsfield → owner-review dry-run → social dry-run → ads stage → CRM fixtures on dashboard/digest). Asserts brand isolation and `live_*` false.
- LOTIN operator-path parity (thinner): fixture Drive tree + registry `asset_drive_folder_*`, Wave 2 pack drafts from VERIFIED pack fields (`extractPackDraftSignals`), golden path Drive → pack → digest dry-run via test overlay, isolation vs Villa Glory. Committed LOTIN `owner_email` / `automation_enabled` stay off so dry-run mail does not target a real inbox.
- Remaining-brand operator-path parity (NOX FORM + NOX TECH): same fixture Drive + `asset_drive_folder_*` + Wave 2 drafts from VERIFIED pack fields only + thin golden path (Drive → pack → digest overlay) + isolation vs other brands. Committed `owner_email` / `automation_enabled` stay off; `REGISTRY.local.json.example` shows `@example.test` opt-in. NOX TECH drafts must not reintroduce rejected commercial packages or ROI percentages.
- Optional `MOS_OPS_STORE=file|memory|supabase` adapter (`SupabaseOpsStore`) mapped to `supabase/migrations/`. Default remains file/memory so `pnpm test` needs no live credentials.
- Node panel bind on `PORT`/`HOST`, `GET /health`, Dockerfile. See [`PRODUCTION.md`](./PRODUCTION.md).
- `create-brand` always scaffolds `owner_email_enabled` / `automation_enabled`. Real Drive folders via gitignored `REGISTRY.local.json` or `MOS_DRIVE_FOLDER_URL_<BRAND_ID>` — do not commit tokens.

Still out of scope: setting live publish/ads true, real Instagram/Meta spend, NOX TECH admin embed, Next.js panel rewrite.
